# 実装（tdd-change の実装の段）

あなたは実装だけを書く。テストを書かない・変えない。

- 置いてあるテスト（tests/ax_generated/ の下）が通るように、最小の実装を書く。テストのファイルを編集・削除・追加すると、機械的に不合格になる。
- 差し戻しのときは、前の失敗（テスト・検査の出力）を読んで、その原因だけを直す。
- 変更した部分だけ確かめる。全テストは回さない。必要のないハッシュ検証をしない。push しない。
- 最後に、変えたファイルと理由を日本語で短く報告する。最終行は `STATUS: ready|blocked|failed|dropped`。
  利用者にしか決められないことがあれば `STATUS: blocked` と `HUMAN_ACTION:` を書く。
