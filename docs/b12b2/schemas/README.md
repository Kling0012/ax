# 行き先スキーマの検査

`schemas/dest/<行き先>.json` は S-6.22 の31行き先に対応する。各ファイルは Draft 2020-12 の閉じたオブジェクトである。未定義の権限項目を追加した本文は通さない。`control.command` の `issued_by` と `decision.record` の `attested` は入口が決める。

## 整合検査

`tools/check_dest_schemas.py` は本体の登録簿と `config/intake-destinations.d/*.yaml` を名前順に読む。最後の定義を使い、不正な置き換えで以前の権限が戻ることを防ぐ。不正な行があっても、別の正常な行は検査対象に残る。

登録行とファイルの欠け・余り、参照先の違い、Draft、識別子、未知項目の拒否、未定義の入力形式と接続先を調べる。外部のスキーマを取得しない。`--facts` に FACTS.md を渡すと、F-15.2 の最後の変更番号と `go.confirm.changes` の上限を照合する。終了コード0は指摘なし、1は指摘ありを表す。

handler が `not-implemented:<理由>` の操作は、実効 Schema に `x-ax-unresolved` を付け、本文の検査より前に 501 `contract_unresolved` を返す。この仮実装は handler の実行を試みない。`tools/check_dest_schemas.py` はこの宣言済みの未実装を許容する。公開した入力形式や接続先を推測で補わない。未決の箇所は build/OPEN.md を参照する。

## go.confirm

`oneOf` で撤去と追認を分ける。撤去には `kind`、`scope`、`excluded`、`changes`、`ratify_approval_id` が必要である。追認には `kind`、`go_md_text`、`go_md_sha256` が必要である。他方の項目を含む本文は拒否する。

`changes` は `all` または1〜14の重複しない整数の配列を受ける。ハッシュは64桁の小文字の16進数である。文字数を制限するため、末尾の改行も通らない。

UTF-8のバイト数、ハッシュの一致、GO.mdの解析、追認の承認状態はスキーマだけでは検証しない。承認側の `go_confirm.validate` が検査する。[承認側の試験](../../../tests/b12b2/intake/test_go.py) と合わせて確認する。

## 試験の対応

| 対象 | この担当の確認 | 別の担当で確認する内容 |
|---|---|---|
| S-6.22 | 31ファイル、登録簿との対応、欠け・余り、Draft、未知項目 | 登録先の処理との接続 |
| T-188 | `tier`・`via` の欠け、不正値、段と `irreversible` の矛盾、正常な別行の保持 | 席と受け口ごとの実行可否 |
| T-193 | 未定義の権限項目の拒否、文字列としての外部文章 | `forged_authority`、表示、承認待ち |
| T-194(g)(j)(m) | `oneOf`、必須項目、未知項目、変更番号、ハッシュの形 | バイト上限、ハッシュ照合、追認の有効性、撤去前の照合 |
| compose | CIのダミー値による `docker compose config`、ポート追加なし、HQの3つのbind | 本物のHQ定義との統合、所有者と権限、接続元uidの検査 |

試験は `tests/b12b2/schemas/` にある。偽の登録簿は `tests/fakes/b12b2/schemas/world.py` が作る。整合検査を単独で確かめるため、偽の世界では未定義の本文を空の閉じたオブジェクトに置き換える。この試験の成功だけでは本番の登録簿を移行可能とは判断しない。

composeの試験はHQの既存サービスを偽のイメージ名で補い、設定を展開するだけである。デーモン、ネットワーク接続、サービスの起動は使わない。
