# 導入ガイド：AX の導入と旧環境からの移行

このガイドは新しく AX を導入する場合と、既存の環境から移る場合を分けて説明する。旧環境からの移行は、その環境の停止対象と利用者の承認を確認してから行う。

## 一般向けの導入

1. [導入手順](../guide/getting-started.md)で前提条件と現在の制限を確認する。設定例は実際の環境に合わせ、資格情報を Git に入れない。
2. [設定例](../guide/templates.md)を参照して、利用するサービス、モデル、権限と接続先を設定する。
3. プロジェクトの登録と初回依頼には[導入例](../guide/example-onboarding.md)を参照する。この例は一連の経路を通した検証がまだ済んでいない。登録、実行経路と権限を確認できなければ依頼しない。
4. 利用できる操作は[CLI リファレンス](../guide/cli.md)で確認する。依頼の受付と作業の完了は別である。結果が不明な場合は同じリファレンスの照合手順に従う。

## 旧環境からの移行

この節は既存の自動化を AX に置き換える場合だけを対象とする。新規導入には旧サービスを停止する必要はない。以下は移行を検討するための確認事項であり、特定の環境にそのまま適用できる停止一覧ではない。

- 旧環境のホスト、サービス、タイマー、入口、保存先と依存関係を現物で確認し、停止対象と保持対象を分ける。確認できない対象は停止しない。
- 構築、資格情報、接続先、停止、退避と外部への変更について、利用者が承認した範囲を記録する。承認されていない変更は行わない。
- 変更前に原本を退避し、退避先と復元方法を確認する。既存の記録やデータの扱いは対象ごとに決める。
- 新しい入口と監視を確認し、旧環境の実行中の作業が終わったことを確かめてから、承認された対象だけを停止する。停止後も状態と接続を確認する。
- 切り替え全体を自動で戻す機能はない。戻す必要がある場合は、対象と方法を個別に確認する。

移行の承認を CLI で追認、書き出し、検証する操作は未実装である。`ax go` と `ax approval` は実行手順として使えない。代替の承認経路はこのガイドでは確認できていないため、移行の実行は保留する。設計上の順序と条件は設計文書（非公開）の S-24 を参照する。
