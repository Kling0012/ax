# 変更受付の運用手順

## 接続前の確認

1. 対象の設定、試験の recipe、CI の出所、禁止パスを確認する。公開 Issue の repo と実装先を取り違えない。
2. 配備側の factory を用意する。`create_ports` に実際の収集、安全審査、検証、権限、カード、通知、公開待ちを渡す。
3. `AX_CHANGE_PORT_FACTORY` に factory を指定する。値は配備の設定で管理する。HTTP、Issue、PR、knob から変更しない。
4. `collect_only` と `dry_run: true` を保ち、予定とノートを確認する。外部操作を許す前に、未接続の部品と検証不能の対象を解消する。

factory が未設定なら、状態に `change_ports_unconfigured` が出る。
そのプラグインのグラフは実行しない。他のサブループは止めない。

## GitHub の資格

資格の複製は FACTS F-3.2 と移行の手順に従い、実環境での作業が許可された段で行う。
既存の `hosts.yml` からトークンだけを読み、`secrets_dir/github-token` へ直接書く。
値を標準出力、ログ、カード、記憶へ出さない。
ファイルの権限は600とする。`hosts.yml` 自体をコンテナへ渡さない。
manifest と Compose は `github-token` という同じ名前を使う。
ジョブ用コンテナや作業者にはこの資格を渡さない。

この成果物の作成中には資格の複製も実 GitHub への接続も行わない。

## 項目の保留と再開

1件の停止は `ChangeFlow.stop(item, reason)` で記録する。
再開は `resume(item)` で停止の印を解除する。
収集側のカード待ち、内部判断待ち、外部状態不明の解除は、理由を確認してから行う。

未信頼 PR は個別指示を受けた後も、通知の配送から30分待つ。
送信上限や配送失敗の時刻から待機時間を数えてはならない。
待機の処理は次の確認時刻を返す。スレッドを30分占有しない。
head や指示が変わった場合は、以前の通知を使わない。

修正が必要なら、修正回数を `change.db` に保存する。
再入場で `tdd-change` を通し、新しい head を検証する。
上限に達した信頼済み PR は証拠付きで内部判断へ回す。
未信頼 PR は同じ判定による免除を使わず保留する。

実装 PR が未作成の案件では、次の順に進める。

1. 候補 head の検証証拠と要求の完了を確認する。
2. 登録済みの実装先へ PR 作成を配送する。
3. 返った repo と PR 番号が登録と一致するときだけ採番し、新しい PR の状態でマージ条件を再照合する。

repo や PR 番号が不足または不一致の配送結果は、採番せず保留する。

## 記録と再配送

`change.db` はマージ、配送、修正回数、項目ごとの停止、学習候補、時系列の送信待ちを保存する。
不明なマージ結果を削除して再実行してはならない。
元の head と PR を照合し、実行済みと確認できた結果だけを公開待ちへ渡す。

`Journal.flush` は未配送の事象を同じ事象 ID で再送する。
学習候補は `pending` から `selected` または `rejected` へ進む。
`selected` の候補だけを `consumed` にできる。
候補の書き込みが失敗しても元の作業を止めない。保存済みの元の事象から回復する。

## ローカルで行う検証

担当の試験は `tests/b14/integration` に置く。
`python3 -m pytest -p no:cacheprovider tests/b14/integration` で実行する。
pytest がない環境では、DECISIONS.md に記録された既存のキャッシュを `PYTHONPATH` へ足す。
新しいパッケージは導入しない。pycache と一時ファイルは `TMPDIR` の下に置く。

T-27 は head、コメント、要求、CI、権限、修正後の再検証、マージ結果の照合を確かめる。
T-28 は個別指示、配送確認、偽時計の30分待機を確かめる。
T-29 は dry-run の既定、項目ごとの停止、質問の経路、記録と再配送を確かめる。
PR 未作成の案件では、検証不備のまま PR 作成を配送しないこと、採番結果が実装先と一致した場合だけマージへ進むことを確かめる。
実行器とグラフの試験にも偽の部品だけを使う。

## 実環境で行う検証

| 対象 | 確かめること |
| --- | --- |
| GitHub | repo ごとの権限、全ページの取得、CI の出所、期待 SHA を指定するマージ |
| カード | 利用者本人の回答と scope、無効化や head の変更を反映すること |
| 通知 | 実際の配送時刻、送信上限、応答が失われた場合の照合と再配送 |
| 公開待ち | repo と PR の一意キー、応答が失われた場合にも重複を作らないこと |
| 検証環境 | b6b と b14b1 の隔離、通信制限、完全な証拠の取得 |
| hibi-server | `env:hub-host-local:hibi-server-e2e` が使えること。使えなければその対象だけを保留すること |
| Compose | 健全性、秘密の渡し先、ホストの待受ポートが増えないこと |

これらは実機でしか確認できない。成果物を作る段では実行しない。
